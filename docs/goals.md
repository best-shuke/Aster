# 持续目标（/goal）

`/goal` 在当前会话创建一个持续目标。主代理执行一轮工作后，运行时用一次无工具的模型请求核对原始目标、验收条件、任务结果和最近的执行证据；有可执行的剩余工作就自动继续下一轮。

```text
/goal 实现用户登录 --criterion "登录成功后进入首页" --criterion "相关测试通过"
/goal start "调研已有材料并撰写综述" --criterion "重要结论有材料来源" --max-rounds 10 --max-seconds 1800
/goal status
/goal pause
/goal resume "目标读者是开发者"
/goal resume --max-rounds 30 --max-seconds 7200
/goal cancel
```

`start` 可以省略；目标恰好以 `status`、`pause` 等子命令开头时，请显式使用 `start`。
带空格的验收条件用引号包围，`--criterion` 可以重复。通过 Shell 单次执行时，可以直接运行：

```sh
./bin/agent /goal start "实现用户登录" --criterion "相关测试通过" --max-rounds 10
```

## 执行与验收

- 每个会话只保留一个当前目标。未完成的目标需要继续或取消后才能创建新目标。
- 工作轮次复用原有文件、命令、MCP、skills、任务验收和多代理运行时，权限保持当前环境的设置。
- 核对请求没有工具权限，返回结构化的进展、验收条件判断、证据与下一步。判断为完成时，运行时还会检查该轮验收、任务计划和团队未完成任务；它们尚未结束时继续推进。
- 代码修改继续受原有验收机制约束：最后一次修改之后需要通过相关独立测试、构建或断言。研究、写作等目标按交付物和来源核对。
- 模型核对是对现有证据的判断，不能替代项目测试、领域专家或用户的最终验收。轮次完成也不等于整个目标完成。
- 答复、工具执行结果与验收进展连续三轮相同时，目标标记为受阻，保留结果供用户调整后继续。

## 预算与控制

默认预算为 **20 个工作轮次、3600 秒活动执行时间**。时间预算覆盖工作与核对请求，并通过截止时间传给本轮工具、子代理及团队；等待用户和暂停期间不计时。当前不提供目标级 Token 预算。

`resume` 的预算参数设置的是**累计总上限**，例如已执行 20 轮后用 `--max-rounds 30`，剩余 10 轮。预算耗尽后需要显式增加相应预算才能继续。单轮仍受原有 `DEEPSEEK_MAX_TASK_SECONDS` 约束。

交互界面在目标运行期间按 `Esc` 或 `Ctrl-C` 暂停，回到输入框后可查看状态、补充要求、取消或恢复。`/goal pause`、`/goal cancel` 是回到输入框之后的命令。目标执行期间，团队不会在工作轮次之外继续后台激活；未完成输入仍按原有团队恢复机制保存。后台 Shell 进程继续遵循原有 `exec` / `monitor` 生命周期。

需要用户决定时，目标进入 `waiting_user`；具体外部阻碍或连续无进展时进入 `blocked`。用 `/goal resume 补充说明` 提供信息并继续。取消或已完成的目标可以创建新的目标，不能恢复原目标。

单次执行的退出码：目标完成或状态管理成功为 `0`，等待输入、受阻或预算耗尽为 `1`，参数错误为 `2`，用户中断为 `130`。

## 保存与恢复

目标描述、验收条件、预算消耗、进展、证据和执行阶段随会话保存在本地会话文件中，包含目标而没有聊天消息的会话也会归档。

程序重新启动时，原先进行中的目标变为暂停，显式运行 `/goal resume` 后继续。中断发生在工作后的核对阶段时，恢复会先完成核对，不重复执行已完成的工作。对中断时结果不确定的工具操作，代理仍需先核实实际状态。

如果暂停后进行了其他对话，恢复时会重新检查目标成果，避免把其他任务的结果当作该目标的验收证据。恢复时补充的要求独立保存，并持续传给后续工作与核对请求。

`/new` 和默认环境切换会创建新会话，目标保留在旧会话；`/resume` 恢复目标，`/resume --messages-only` 只复制消息。`/env ... keep` 保留当前会话和目标。

目标内容和证据属于会话数据，遵循现有私密数据与 Git 策略。
